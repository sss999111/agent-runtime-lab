# 实验 002：三层记忆

## 目标

验证三层记忆（L1 工作记忆 / L2 情景轨迹 / L3 长期事实）是否真的能影响后续任务的行为，并用对照组证明没有记忆时任务不可完成。

## 实现

- `runtime/memory.py`：`MemoryStore`，长期事实存 `workspace/.memory/facts.jsonl`，情景轨迹存 `workspace/.memory/episodic.jsonl`。长期事实按字符 n-gram 余弦相似度检索，只注入 top-k 相关条目；情景轨迹按最近 N 条取。该检索基于字面相似度，不是语义 embedding。
- `runtime/tools.py`：新增 `remember(content)` 工具，让 Agent 显式写入长期事实。
- `runtime/agent.py`：任务开始时把记忆块拼到**系统提示**最前面；任务结束时自动把任务摘要写入情景轨迹。

## 复现命令

```
python bench.py --reset-memory --tasks task_013,task_014 --repeat 2
python bench.py --reset-memory --tasks task_014 --repeat 2
```

## 任务

- `task_013`：调用 `remember` 写入事实“项目代号是 Phoenix”。
- `task_014`：把项目代号写到 `out/codename.txt`。这个代号只能从记忆里获得，文件里没有。

## 结果

| 组别 | task_014 通过 | 平均步数 | 平均合计 tokens |
|---|---|---|---|
| 有记忆（先跑 013 写入代号，再跑 014） | **2/2** | 2.5 | 1,966 |
| 无记忆（只跑 014） | **0/2** | 8.0（跑满最大步数） | 9,488 |

数据来源：`logs/bench_full_20261115_212430.csv`、`logs/bench_full_20261115_212506.csv`。

说明：有记忆组共 4 次运行，其中 2 次是 `task_013`（写入代号）本身，必然成功，不计入对比；真正可比的是 `task_014` 在有/无记忆下的 2 次与 2 次。

## 结论

1. **长期事实能把不可完成的任务变成 2.5 步完成**：对照组不知道代号，反复列文件、读配置，8 步耗尽仍失败；实验组直接从记忆取出代号。
2. **情景轨迹自动工作**：每个任务结束都会写入 `episodic.jsonl`，包含任务、结果、步数，可用于后续跨任务上下文。
3. **格式化类偏好遵守率低**：早期测试让模型记住“报告用 markdown 格式”，即使注入到系统提示，lite 模型仍有较大概率输出纯文本。说明软偏好的遵守依赖模型能力，事实检索类记忆更稳定可靠。

## 局限

- 检索用的是字符 n-gram 字面相似度而不是语义 embedding：同义改写（如「代号」vs「别名」）召回不佳，事实量大时仍需重排或引入真正的向量模型。
- 没有重要性评分和遗忘机制，所有事实平等保留。
- 对照组跑满 8 步，说明模型在信息缺失时不会主动承认不知道，而是浪费步数试探——这正是调度器要解决的问题。
